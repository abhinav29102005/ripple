## 2. Product in one paragraph

When a clinical trial is retracted, its data often stays inside systematic reviews, which feed guidelines and organizational decisions. **Ripple is a team of agents that uses FalkorDB as its shared brain to find every review, guideline, and decision that depended on a retracted trial, quantify how the evidence changes, tell the right people, and remember how each team handles such alerts.** The agents coordinate through graph tasks (surviving crashes), keep isolated per-team memory (surviving restarts), and explain every ranking as a path through the graph.

**Pitch line:** *A retraction is one deleted node in one place and a silent error in dozens of others. Ripple finds them, tells the right people, and remembers how your team handles them.*

## 4. Architecture

Three kinds of graph in one FalkorDB instance:

- **`knowledge`** (shared, read-mostly): evidence graph (trials, reviews, guidelines, retractions) merged with the synthetic organization (people, committees, decisions, documents, tickets, messages, topics). One graph so multi-hop queries can cross from a Retraction to a Person in a single traversal.
- **`coord`** (shared, write-heavy): tasks, agents, leases, dependencies.
- **`tenant_<id>`** (one per team, isolated): sessions, messages, episodes, facts, rules, rankings. Seed two teams: `tenant_cardio` and `tenant_onco`.

Queries do not span graphs. The application layer joins them by external ids (trial id, review id, guideline id stored as properties in tenant graphs).

### Agents (worker processes, one Python loop each)

| Agent | Claims task type | Produces |
|---|---|---|
| Watcher | `ingest_retraction` | Retraction node (reason category extracted from notice text; LLM with regex/keyword fallback), then spawns `trace` |
| Tracer | `trace` | Blast-radius result; staleness propagation on decisions; spawns one `quantify` per affected review and one `brief` depending on all of them |
| Statistician | `quantify` | `Impact` node per review: pooled effect before and after, percent change, flips |
| Briefer | `brief` | Per-tenant ranked alerts (using that tenant's rules) and a template or LLM notice draft |
| Librarian | `consolidate` | Rules created, updated, or retired from recent episodes; facts superseded |

Plus: FastAPI backend, MCP server, Analyst agent (LLM tool-calling over MCP tools, with deterministic fallback), single-page UI.

### Stack

- Python 3.12, FastAPI, uvicorn, `falkordb` Python client (sync is fine; async client optional), `mcp` SDK (FastMCP), `pytest`, `httpx`.
- LLM adapter in `ripple/llm.py`: provider and model from env (`LLM_PROVIDER`, `LLM_MODEL`, API key var). Only used for: notice parsing, notice drafting, chat answers, Analyst tool-calling. Everything has a template fallback.
- UI: one static page (`ui/index.html`, vanilla JS) served by FastAPI; force-graph library from a CDN; polling every 1 to 2 seconds for the task board (no websockets needed).
- Docker Compose: `falkordb` service (port 6379, plus the browser UI port) with a persistent volume, and `api` plus worker services. Local run must work with `docker compose up`.

## 6. Graph data models

### 6.1 `knowledge` graph

**Evidence nodes**

- `Trial {id, title, year, status, synthetic}` where `status` is `active` or `retracted`
- `Review {id, title, year, model, synthetic}`
- `Guideline {id, title, body_org, year, synthetic}`
- `Retraction {id, date, reason, reason_category, notice_url, synthetic}`; `reason_category` is one of `fabrication`, `error`, `administrative`, `unknown`
- `Journal {name}`
- `Impact {id, review_id, retraction_id, before, before_lo, before_hi, after, after_lo, after_hi, pct_change, flips, computed_at}`

**Organization nodes (all synthetic)**

- `Person {id, name, role}`, `Committee {id, name}`, `Decision {id, title, date, status, risk_reason}` where `status` is `active` or `at_risk`
- `Document {id, kind, title}`, `Ticket {id, status, priority, title}`, `Message {id, channel, text, ts}`, `Topic {name}`

**Edges**

- `(Retraction)-[:RETRACTS]->(Trial)`
- `(Trial)-[:INCLUDED_IN {yi, sei}]->(Review)`; `yi` is the effect (for example log odds ratio), `sei` its standard error
- `(Review)-[:INFORMS]->(Guideline)`
- `(Trial)-[:PUBLISHED_IN]->(Journal)`
- `(Review)-[:SHARES_TRIAL {n}]->(Review)` (derived, for clustering)
- `(Impact)-[:OF]->(Review)`
- `(Person)-[:MEMBER_OF]->(Committee)`; `(Committee)-[:OWNS]->(Guideline)`
- `(Decision)-[:ABOUT]->(Guideline)`; `(Decision)-[:BASED_ON]->(Review)`; `(Decision)-[:MADE_BY]->(Committee)`
- `(Person)-[:PARTICIPATED_IN]->(Decision)`; `(Person)-[:AUTHORED]->(Review)`
- `(Document)-[:SUPPORTS]->(Decision)`; `(Message)-[:MENTIONS]->(Decision)`; `(Ticket)-[:TRACKS]->(Decision)`
- `(Review)-[:ON]->(Topic)`; `(Guideline)-[:ON]->(Topic)`

### 6.2 `coord` graph

- `Task {id, key, type, status, priority, created, lease_until, attempts, max_attempts, claimed_by, payload, result, error}`; `status` is `queued`, `claimed`, `done`, or `failed`; `key` is a unique idempotency key
- `Agent {id, role, started, heartbeat}`
- Edges: `(Task)-[:DEPENDS_ON]->(Task)`, `(Task)-[:SPAWNED]->(Task)`, `(Task)-[:CLAIMED_BY]->(Agent)` (optional; `claimed_by` property is the source of truth)

### 6.3 `tenant_<id>` graph

- Conversation: `Session {id, started}` with `(Session)-[:FOLLOWS]->(Session)`; `Message {id, seq, role, text, ts}` with `(Session)-[:HAS]->(Message)`
- Episodic: `Episode {id, ts, kind, reason, weight_bucket, flips, ext_review, ext_retraction}` where `kind` is `dismiss`, `escalate`, `correct`, or `note`; `(Episode)-[:IN]->(Session)`
- Semantic: `Watch {topic}`; `Fact {id, key, value, valid_from, valid_to}` with `(Fact)-[:SUPERSEDES]->(Fact)` (never overwrite, supersede)
- Procedural: `Rule {id, feature, value, delta, support, hit_rate, status, created, updated}`; `(Rule)-[:LEARNED_FROM]->(Episode)`; `status` is `active` or `retired`
- Explanations: `Ranking {id, ts, retraction_id}`; `(Ranking)-[:USED {delta}]->(Rule)`; `(Ranking)-[:RANKED {rank, score, base}]->(Item)` where `Item {id, ext_id, kind}` references a review id

## 7. Query library (illustrative; test and adapt)

### 7.1 Coordination (`coord.py`)

**Atomic claim:**

```cypher
MATCH (t:Task {status: 'queued', type: $type})
OPTIONAL MATCH (t)-[:DEPENDS_ON]->(d:Task) WHERE d.status <> 'done'
WITH t, count(d) AS open WHERE open = 0
WITH t ORDER BY t.priority DESC, t.created ASC LIMIT 1
SET t.status = 'claimed', t.claimed_by = $agent,
    t.lease_until = $now + $lease, t.attempts = t.attempts + 1
RETURN t.id AS id, t.payload AS payload
```

**Compare-and-set fallback** (pick a candidate with a read, then claim conditionally and treat zero returned rows as "lost the race, try again"):

```cypher
MATCH (t:Task {id: $id, status: 'queued'})
SET t.status = 'claimed', t.claimed_by = $agent, t.lease_until = $now + $lease, t.attempts = t.attempts + 1
RETURN t.id AS id, t.payload AS payload
```

**Heartbeat (extend lease while working):**

```cypher
MATCH (t:Task {id: $id, claimed_by: $agent, status: 'claimed'})
SET t.lease_until = $now + $lease
RETURN t.id
```

**Complete / fail:**

```cypher
MATCH (t:Task {id: $id, claimed_by: $agent, status: 'claimed'})
SET t.status = 'done', t.result = $result
RETURN t.id
```

On failure: if `attempts < max_attempts`, set `status = 'queued'` and `claimed_by = null`; otherwise `status = 'failed'` and store `error`.

**Reclaim expired leases** (any worker runs this every few seconds):

```cypher
MATCH (t:Task {status: 'claimed'}) WHERE t.lease_until < $now
SET t.status = 'queued', t.claimed_by = null
RETURN count(t) AS reclaimed
```

**Spawn with idempotency and dependencies:** `MERGE (t:Task {key: $key})` then `ON CREATE`-style initialization (or set only if missing), then `MATCH` and `MERGE` `DEPENDS_ON` edges. Task keys: `ingest:<retraction_id>`, `trace:<retraction_id>`, `quantify:<retraction_id>:<review_id>`, `brief:<retraction_id>`, `consolidate:<tenant>:<n>`.

### 7.2 Knowledge: blast radius, staleness, ownership

**Blast radius:**

```cypher
MATCH (r:Retraction {id: $rid})-[:RETRACTS]->(t:Trial)-[i:INCLUDED_IN]->(rev:Review)
OPTIONAL MATCH (rev)-[:INFORMS]->(g:Guideline)
RETURN t.id AS trial, rev.id AS review, i.yi AS yi, i.sei AS sei, collect(DISTINCT g.id) AS guidelines
```

**At-risk decisions and who to notify:**

```cypher
MATCH (r:Retraction {id: $rid})-[:RETRACTS]->(t:Trial)-[:INCLUDED_IN]->(rev:Review)
MATCH (d:Decision)-[:BASED_ON]->(rev)
OPTIONAL MATCH (d)-[:MADE_BY]->(c:Committee)<-[:MEMBER_OF]-(p:Person)
RETURN d.id AS decision, rev.id AS review, c.name AS committee, collect(DISTINCT p.name) AS notify
```

**Staleness propagation:**

```cypher
MATCH (r:Retraction {id: $rid})-[:RETRACTS]->(:Trial)-[:INCLUDED_IN]->(rev:Review)<-[:BASED_ON]-(d:Decision)
SET d.status = 'at_risk', d.risk_reason = 'retraction ' + r.id
RETURN count(DISTINCT d) AS flagged
```

**Decision trace (a decision back to its source, with supporting documents and chats):**

```cypher
MATCH (d:Decision {id: $did})-[:BASED_ON]->(rev:Review)
OPTIONAL MATCH (t:Trial)-[:INCLUDED_IN]->(rev)
OPTIONAL MATCH (r:Retraction)-[:RETRACTS]->(t)
OPTIONAL MATCH (doc:Document)-[:SUPPORTS]->(d)
OPTIONAL MATCH (m:Message)-[:MENTIONS]->(d)
RETURN d, rev, collect(DISTINCT t) AS trials, collect(DISTINCT r) AS retractions,
       collect(DISTINCT doc) AS documents, collect(DISTINCT m) AS messages
```

**Who knows about a topic (rewrite with `OPTIONAL MATCH` if the pattern predicate fails):**

```cypher
MATCH (p:Person)-[:AUTHORED|PARTICIPATED_IN]->(x)
WHERE (x)-[:ON]->(:Topic {name: $topic}) OR (x)-[:ABOUT]->(:Guideline)-[:ON]->(:Topic {name: $topic})
RETURN p.name AS person, count(DISTINCT x) AS evidence ORDER BY evidence DESC LIMIT 5
```

**Contamination clusters (derived edges, then a built-in algorithm per Spike D):**

```cypher
MATCH (a:Review)<-[:INCLUDED_IN]-(t:Trial {status: 'retracted'})-[:INCLUDED_IN]->(b:Review)
WHERE a.id < b.id
WITH a, b, count(t) AS n
MERGE (a)-[s:SHARES_TRIAL]->(b) SET s.n = n
```

Then weakly connected components or community detection over `Review` with `SHARES_TRIAL`. Meaning: two reviews pooling the same retracted trial are not independent evidence, so a cluster magnifies the damage.

**Guideline criticality:** PageRank or in-degree over `INFORMS` and `BASED_ON` (per Spike D).

### 7.3 Tenant memory (`memory.py`)

- Create session and message, fetch last N messages of the session chain (`FOLLOWS` path).
- Record episode: `CREATE (e:Episode {...})`, link to the session.
- Fetch recent episodes for consolidation, by `ts` descending.
- Create or update rule, `LEARNED_FROM` edges to supporting episodes.
- Supersede fact: set `valid_to` on the old fact, create the new fact, add `SUPERSEDES`.
- Record ranking: create `Ranking`, `RANKED` edges to `Item` nodes, `USED` edges to each applied rule (with `delta`).
- Explain: from a `Ranking` and an `Item`, return the applied rules and their `LEARNED_FROM` episodes (this is the "why" path shown in the UI and chat).

## 8. Core logic

### 8.1 Pooled effect (`stats.py`, pure Python, unit-tested)

Inverse-variance fixed effect: `w_i = 1 / sei_i^2`; `pooled = sum(w_i * yi_i) / sum(w_i)`; `se = sqrt(1 / sum(w_i))`; 95% CI `pooled ± 1.96 * se`. Optional DerSimonian-Laird random effects: `Q = sum(w_i * (yi_i - pooled)^2)`, `tau2 = max(0, (Q - (k-1)) / (sum(w) - sum(w^2)/sum(w)))`, then weights `1 / (sei^2 + tau2)`. Compute "before" (all included trials) and "after" (excluding retracted trials). `pct_change = (after - before) / abs(before)`. `flips` is true if the sign changes or the 95% CI crossing zero status changes.

**Required unit test vector** (fixed effect):

| Trial | yi | sei |
|---|---|---|
| A | -0.4 | 0.20 |
| B | -0.5 | 0.25 |
| C (retracted) | -0.9 | 0.15 |

- Before: pooled ≈ -0.6788, se ≈ 0.1082, CI ≈ (-0.891, -0.467)
- After (C removed): pooled ≈ -0.4390, se ≈ 0.1562, CI ≈ (-0.745, -0.133)
- `pct_change` ≈ 0.353 in magnitude (effect attenuates by about 35 percent), `flips` false

Add a second test where removal makes the CI cross zero and `flips` is true.

### 8.2 Severity and tenant ranking (`ranking.py`)

Per affected review (an "alert"):

- `reason_w`: fabrication 1.0, error 0.6, unknown 0.5, administrative 0.2 (use the notice's category only)
- `weight_share`: the retracted trial's weight divided by total weight in that review
- `flips`: 1 or 0 from the Impact node
- `guideline_count`: guidelines informed by the review
- `base = 0.4*reason_w + 0.3*weight_share + 0.2*flips + 0.1*min(guideline_count/3, 1)`

Alert features for rules: `reason` (category), `weight_bucket` (`low` if share < 0.10, `mid` if 0.10 to 0.30, `high` if above 0.30), `flips` (true or false).

Tenant score: `clamp(base + sum(delta of active rules whose (feature, value) matches the alert), 0, 1)`. Record a `Ranking` with `USED` edges for every applied rule. Sort descending.

### 8.3 Consolidation (Librarian)

Per tenant, per `(feature, value)` bucket, over episodes since the last run:

- 3 or more episodes with dismiss rate at least 0.8: create or update a rule with `delta = -0.3`.
- 3 or more episodes with escalate rate at least 0.8: `delta = +0.3`.
- A new episode that contradicts an active rule lowers its `hit_rate`; below 0.5, set `status = 'retired'`.
- Fact changes are superseded (set `valid_to` on the old one, link `SUPERSEDES`).
- Optionally phrase each rule in plain English for the UI (LLM optional, template fallback required).

Deterministic and unit-tested. Add a test that three dismissals of `administrative` alerts produce a rule that lowers the score of the next `administrative` alert.

### 8.4 Cross-session recall (chat)

`POST /api/chat {tenant, session, text}` persists the message, then builds context from the last N messages of the session chain plus episodes and rules reachable from the topic or item mentioned. "Why is this alert ranked low?" returns the ranking path: rules used, and the episodes that created them. With `LLM_MODE=off`, return a templated answer built from the same path. Restarting every process must not change the answer.

## 9. Agents (worker loop)

`agents/runner.py`: a generic loop used by all workers.

```
register Agent node; loop:
  every ~5s: run reclaim_expired_leases (any worker may do it)
  task = claim(type=my_type); if none: sleep 0.5s; continue
  start heartbeat thread extending lease while the handler runs
  try: result = handler(task.payload); complete(task, result)
  except: fail(task, error) (requeue until max_attempts)
```

Handlers are idempotent (safe to run twice, since a crashed worker's task is re-run). Use `MERGE` for created nodes. Task DAG per retraction: `ingest -> trace -> (quantify x N) -> brief`. The Tracer spawns `quantify` tasks and a `brief` task that `DEPENDS_ON` all of them, so the Briefer only runs after every quantify is done (the claim query enforces this).

### 10.2 Analyst agent (`analyst.py`)

LLM tool-calling over the MCP tools. System prompt: pick the fewest tools needed, always cite node ids, never recommend changing clinical practice. Log every tool call and result to a `ToolCall` node in `coord` (or the tenant graph) so the UI can show the trace. Deterministic fallback (`LLM_MODE=off`): a fixed plan that calls `blast_radius`, `rank_guidelines`, `contamination_clusters`, `recall_team_history`, then opens a ticket for the top item.

### 10.4 UI (`ui/`)

Four panels with a tenant switcher (Cardio, Onco) and a retraction picker:

1. **Graph explorer:** force-graph of the blast radius, path highlighted, click a node for details and sources.

## 16. Risks and fallbacks

| Risk | Fallback |
|---|---|
| Claim not atomic under concurrency | Compare-and-set claim; else serialize claims via one coordinator process; document it |
| Persistence fails on restart | Fix the volume and persistence settings; do not build more until Spike A passes |
| A built-in algorithm is unavailable | Fetch the subgraph with Cypher and compute in Python; say so in the README |
| LLM or network failure | `LLM_MODE=off` templates for every step |
| Pattern predicates or other Cypher features unsupported | Rewrite with `OPTIONAL MATCH`; log it |
| Running out of time | Follow the cut order in section 12; protect the Track 02 slice |
| Scope creep | If it does not serve the retraction-impact story or a hero proof, do not build it |
